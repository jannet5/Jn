# 內容策略：Hook 公式庫與排卡模板

> 這份文件回答兩個問題：封面怎麼寫才會停下滑動的手指、整副牌怎麼排才會被滑到最後。
> 鐵律：**所有數字必須出自素材或可考證**。查無來源 → 換非數字公式，不准編。

## 一、封面 Hook 公式（六選一）

| # | 公式 | 結構 | 範例骨架（DSL） | 使用條件 |
|---|------|------|----------------|----------|
| 1 | 數字反差 | N% 還在 A ／ M% 已經 B | `# !!99%!! 的人還在寫 Prompt`<br>`# ==1%== 的人在寫 Loop` | 數字可考證，否則禁用 |
| 2 | 痛點提問 | 做完 X 就以為結束了？ | `# 寫完 Prompt`<br>`# 就當!!完成!!？` | 痛點必須是受眾真的會踩的 |
| 3 | 認知顛覆 | 你以為 A，其實 B | `# 你以為是工具問題`<br>`# 其實是==流程問題==` | B 要在內容卡裡撐得起來 |
| 4 | 清單承諾 | N 個 X，一次講完 | `# !!6 個!!必裝工具`<br>`# 一次講完` | N 與實際內容相符（lint 會核對「N 張」） |
| 5 | 身分呼喚 | 給每天都在 X 的你 | `# 給每天被會議`<br>`# ==塞爆==的你` | 受眾輪廓明確時最有效 |
| 6 | 時間承諾 | N 分鐘搞懂 X | `# !!90 秒!! 分清楚`<br>`# ==三個名詞==` | 內容真的能在短時間讀完 |

封面必備三件套：`[badge]` 定調（領域 · 年份）、hook 大標（至少一處 `!!` 或 `==`，lint 強制）、一句副標把承諾說完整。

### 封面行銷準則：先共鳴，再講結論

封面不是摘要，也不是課程標題頁。封面只做一件事：讓對的人覺得「這不就是我嗎？」然後願意滑下一張。

優先順序：

1. **讀者心裡話**：把素材中的真實抱怨、疑問、卡關感放到主標。例：「每天用 AI，怎麼還是沒變快？」
2. **痛點反差**：主標要有「明明 A，卻 B」的張力。例：「AI 都在用了，怎麼還是沒變快？」
3. **視覺素材抓核心行為**：封面 visual 依內容選對變體，不要只放工具名稱——`pain-flow`＝痛點循環，呈現讀者正在重複做的核心動作（例：`問 AI -> 複製貼上 -> 自己修錯` 比 `ChatGPT -> VS Code -> 報錯` 更準）；`checklist`＝「你中了幾個」未勾選清單，適合自我檢測型 hook；`vs`＝新舊對立（左✕右✓），適合認知顛覆型 hook。
4. **口語流暢**：用人會說出口的句子，不用抽象名詞開場。少用「工作流、模型、流程、效率」當主標第一眼，除非它們包在問題句裡。
5. **易讀短句**：主標 2 行以內，每行約 8–13 字；副標 1–2 短句，每行約 20 字內。不要讓 highlight 膠囊跨太長句子。
6. **副標只補刀**：副標不是解釋全文，而是加深共鳴或補一個轉折。例：「你不是不努力，是還在自己接回專案。」

封面 rewrite 公式：

| 情境 | 不夠好的寫法 | 更好的寫法 |
|------|--------------|------------|
| 作者結論太早 | `# 你還停在複製貼上流程` | `# AI 都在用了`<br>`# 怎麼還是!!沒變快!!？` |
| 抽象名詞太多 | `# 卡住的不是模型，是流程` | `# 明明用了 AI`<br>`# 卻還是!!自己收尾!!？` |
| 像課程標題 | `# AI Agent 工作流入門` | `# 不想再複製貼上`<br>`# 你該認識==AI Agent==` |
| 缺少讀者視角 | `# AI 從顧問變隊友` | `# 每次問完 AI`<br>`# 還是你自己改？` |

## 二、排卡結構模板（五選一）

**教學型**（觀念 → 方法）
```
1 @cover  hook（[hero] 巨型數字/關鍵詞當唯一主角）
2 @point  痛點共鳴：列出讀者正在踩的坑（編號盒或 [bar] 對比時間）
3 @point  觀念翻轉：舊做法 vs 新做法（[vs] 左右對比 或 [flow]）
4-6 @point/@code  方法步驟：一卡一步，能上程式碼就上 @code、有畫面就 [shot]
7 @point  金句收束：[big] 或引言單獨成卡＝自動全版金句卡
8 @recap  回顧：自動彙整各卡標題（儲存率槓桿）
9 @cta    行動
```

**清單型**（N 個 X）
```
1 @cover  hook（清單承諾）
2 @point  為什麼重要／怎麼挑的（[stat] 放關鍵數字）
3-6 @point  清單本體：每卡 2–3 項，用條列盒，不要一卡塞完
7 @point  從哪一個開始（給行動起點，[check] 自檢清單）
8 @recap  回顧
9 @cta    行動
```

**對比型**（錯誤 vs 正確）
```
1 @cover  hook（痛點提問）
2 @point  錯誤示範：[no] + 後果（或 [chat] 重現踩坑對話）
3 @point  正確示範：[ok] + 原理
4 @point  為什麼差這麼多（[vs] 左右對比 或 [flow] 拆解）
5 @point  自檢清單（[check]）
6 @cta    行動
```

**故事型**（真實情境開場 → 轉折 → 方法 → 金句）
```
1 @cover  hook（痛點提問或身分呼喚）
2 @point  真實情境開場：[chat] 或 [timeline] 重現當下場景
3 @point  轉折：發生了什麼讓情況改變
4-6 @point/@code  方法：怎麼做到的，一卡一步
7 @point  金句收束：[big] 或引言（帶出處 `>—`）單獨成卡
8 @recap  回顧
9 @cta    行動
```

**迷思破解型**（連續 `[no]`→`[ok]` 或用 `[vs]` 呈現「迷思 vs 真相」逐條破解，適合認知顛覆 hook）
```
1 @cover  hook（認知顛覆）
2-5 @point  逐條破解：每卡一個迷思，[no] 迷思 + [ok] 真相（或 [vs] 左＝迷思、右＝真相）
6 @point  總結：這些迷思共同的根源
7 @recap  回顧
8 @cta    行動
```

**元件選用原則**：數字是主角用 `[stat]`、差距要看得見用 `[bar]`、A/B 張力用 `[vs]`、情境重現用 `[chat]`、真實畫面用 `[shot]`、要人照著做用 `[check]`、演進/歷程用 `[timeline]`、完成度/佔比用 `[ring]`、金句要可信度就帶出處（`>—`）。同一副牌每種視覺元件以 1–2 次為限，重複出現會鈍化。

## 三、每卡規則

- **3 秒測試**：只看大標（##）能否知道這卡在講什麼。不行就重寫標題。
- **一卡一概念**：一張 @point 只允許一個 `##`（lint 強制）。想講兩件事就拆兩張。
- **字數上限**：cover ≤ 60、point ≤ 160、cta ≤ 70（criteria 可調；計字不含 badge 與程式碼）。
- **結構優先**：內容盡量落在元件裡（清單盒、對照盒、flow、引言），避免整卡裸段落——與 course-page-generator 的「避免 loose-text」同一原則。
- **節奏**：相鄰兩卡的主元件換版型（lint 會提醒）。連續兩卡都是編號盒，滑起來像同一張。
- **收尾鉤（選用）**：卡片最後一行可以埋「下一張：⋯⋯」帶動繼續滑。

## 四、CTA 公式

`價值預告 ＋ 行動動詞 ＋ 留言「關鍵字」`

- 價值預告：下一篇主題、可領取的資源（清單、模板、範例包）
- 行動動詞：追蹤／留言／收藏／分享 擇一以上（lint 強制）
- 留言關鍵字：`留言「XXX」`格式（lint 強制）——這是演算法互動的槓桿，也是 promo-writer 產 caption 時要回收的錨點
- 追蹤膠囊與 handle 由模板自動注入，content.md 不用寫

## 五、產出後自檢（跑 lint 前先人工過一輪）

- [ ] 封面 hook 是否 3 秒內看得懂、且內容卡撐得起這個承諾？
- [ ] 封面是不是讀者會說出口的話，而不是作者想講的結論？
- [ ] 封面主標是否 2 行內、每行 8–13 字左右，副標是否短到不用回讀？
- [ ] 每個數字都指得出來源？
- [ ] 有沒有 AI 腔（以下是、總而言之⋯⋯）？
- [ ] 每張卡拿掉其他卡單獨看，還有價值嗎？
- [ ] CTA 的關鍵字，之後 caption 會不會回收使用？
- [ ] 統計主張都有 source 註解？
